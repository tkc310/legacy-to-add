# よくある質問

English FAQ: [FAQ](../faq.md).

## なぜ SKILL.md は日本語なのですか

このスキルは日本語で書き、試したものです。インストーラが同じ成果物を読み込むよう、このリポジトリではそのファイルを変更せずに置いています。翻訳を併置すると、正本が二つになります。英語の入口は [README.md](../../README.md) と [`docs/`](..) です。

## リポジトリ名は `legacy-to-add` ですが、スキル名ですか

違います。インストールするスキルの `name` は `legacy-to-ai-ready` で、コピーするフォルダは `skills/legacy-to-ai-ready/` です。公開先の GitHub リポジトリは [`tkc310/legacy-to-add`](https://github.com/tkc310/legacy-to-add) です。呼び出すときはスキル名（`/legacy-to-ai-ready`）を使ってください。

## このスキルは、レガシーシステムを代わりに書き直しますか

書き直しません。エージェントと、それを指示する人のための手順です。エージェントは、診断、特性テスト、守られた範囲の修正など、段階に沿って *対象* プロジェクトを変更することがあります。ただし、このリポジトリ自体に製品のコードはなく、スキルは一括の書き直しを禁止しています。

## 人のレビューは、もう不要ですか

不要にはなりません。このスキルがなくそうとしているのは、「人が差分の全行を読むこと」を安全性の保証にすることです。何が正しいかの決定、方針書の承認、挙動を変える変更の取り込み、検査を緩める変更の承認、取り消せない操作の承認は、人に残ります。詳しくは [使い方](usage.md#人に残る判断) を見てください。

## 段階を飛ばしてもよいですか

領域ごとに段階1〜2を回すこと、段階2の途中でテストの自動実行のような最小限の仕組みを入れることはできます。予定した領域の振る舞いが固まる前に、リポジトリ全体へ厳しい lint や型の規約を一斉適用しないでください（それは段階3です）。1回きりの事例だけで改善ループ（段階5）を始めないでください。その種類の変更について、検査が実際に誤りを止めたことを確かめる前に、人のレビューを外さないでください。

## 使うために pstack や Lauren Tan（@poteto）氏のスキルが必要ですか

必要ありません。このスキルの「人のレビューに頼らない」構成は、Lauren Tan 氏の公開投稿、pstack の公式ガイド、pstack に同梱されたスキルを参考にしています。出典はスキル本文に書いてあります。同梱スキルの名前やスラッシュコマンドは、特定のツール向けです。使う環境にあるかは、確認が必要です。使えない場合は、本文に書いた要件を満たすものを、プロジェクトに合わせて作ってください。

同氏の長文記事（Loops You Can Trust、The Complete Guide to pstack の Pt. 1 と Pt. 2）は、スキルを書いた時点で原文の全文を取得していないため、スキル本文では引用していません。

## スキルに「要確認」とある数値には、何を書けばよいですか

問数の上限、カバレッジの目標、再発回数の閾値などは、スキルでは決めていません。方針書に仮の値を置き、「要確認」と書いて、プロジェクトの実測のあとで見直してください。

## 方針書や用語集は、どこに置けばよいですか

*対象* プロジェクトの、バージョン管理された1か所に置き、その場所を方針書に書いてください。このリポジトリが配布するのはひな型だけです。置き場所の例は [使い方](usage.md#対象プロジェクトでの置き場所の例) にあります。

## エージェントが英語で作業しています。日本語のスキルは使えますか

多くの場合、使えます。エージェントは日本語の手順を読み、依頼すれば英語で報告できます。仮説、用語集、ADR は、承認する人が読めるよう、そのプロジェクトですでに使っている言語で書いてください。

## インストール済みのコピーを更新するには

選んだインストール先へ、`skills/legacy-to-ai-ready/` フォルダを再度コピーしてください。詳しくは [インストール](installation.md#更新) を見てください。
