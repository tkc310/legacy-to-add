# feature map（機能全体のマップ）

ユーザー視点で、アプリの全機能を地図にした文書。人とエージェントが、機能や画面を同じ名前で呼ぶために使う。段階3の検証スキルは、このマップを機能の一覧として使う。

- 版: （更新日）
- 対象のアプリと範囲:
- 用語集の場所:
- 仕様書の場所:

## 書き方の規則

- 領域名、機能名、画面名には、用語集の用語を使う。用語集にない名前は書かない。先に、仮説の用語として登録する。
- 識別子は変えない。名前を変えるときは、用語集を先に直し、同じ変更の中でこのマップと仕様書を直す。
- 状態が仮説の行には、根拠を必ず書く。確定にするのは、決定者の確認のあとである。
- 操作の手順と、観察できる結果は、仕様書に書く。ここには書かない。
- 動かして確かめていない機能は、「未確認」と書く。
